## 3.5 ORDER BY: ordenar el resultado

```sql
SELECT nombre, precio
FROM productos
ORDER BY precio DESC;
```
| nombre | precio |
|---|---|
| Detergente | 12.90 |
| Yogurt 1L | 6.80 |
| Leche 1L | 5.20 |
| Gaseosa 1L | 4.50 |
| Arroz 1kg | 4.00 |

- `ASC` (ascendente) es el valor por defecto; `DESC` es descendente.
- **Varias columnas:** la segunda desempata a la primera. `ORDER BY categoria, precio DESC`.
- 🎲 **"Sin ORDER BY no hay orden."** Aunque hoy salgan ordenadas, mañana pueden salir distinto.

### Lo que el manual no dice
| Tema | Regla | Para recordar |
|---|---|---|
| NULL al ordenar | En PostgreSQL, NULL es **el valor más grande**: con `ASC` queda al final y con `DESC` al principio | 🎈 *"El NULL es el más grande: sube con DESC, baja con ASC."* |
| Controlar los NULL | `ORDER BY ciudad DESC NULLS LAST` / `NULLS FIRST` | |
| Empates | Ana y Rosa (ambas de Lima) pueden salir en cualquier orden → `ORDER BY ciudad, nombre` | 🎯 *"Si dos filas pueden empatar, desempata."* |
| Alias | Se puede ordenar por un alias del SELECT | |
| `ORDER BY 2` | Ordena por la 2.ª columna. Evitarlo: se rompe si cambian las columnas | 🚫 *"Ordena por nombre, no por número."* |

## 3.6 Funciones de agregación y GROUP BY

### Agregar: muchas filas → un solo valor
```sql
SELECT COUNT(*)   AS pedidos,
       SUM(monto) AS total,
       AVG(monto) AS promedio,
       MIN(monto) AS minimo,
       MAX(monto) AS maximo
FROM pedidos;
```
| pedidos | total | promedio | minimo | maximo |
|---|---|---|---|---|
| 8 | 99.90 | 12.4875000000000000 | 4.00 | 20.40 |

`AVG` sale con muchos decimales → `ROUND(AVG(monto), 2)`.

### Las tres formas de COUNT
| Expresión | Cuenta | En `empleados` |
|---|---|---|
| `COUNT(*)` | Todas las filas | 6 |
| `COUNT(jefe_id)` | Filas donde jefe_id **no es NULL** | 5 |
| `COUNT(DISTINCT jefe_id)` | Valores **distintos** no nulos | 3 |

> 🔢 *"COUNT estrella cuenta filas; COUNT columna cuenta valores; COUNT DISTINCT cuenta valores únicos."*

### Reglas de las agregaciones
- **Ignoran los NULL** (excepto `COUNT(*)`). `AVG` promedia **solo las filas con valor**.
- **MIN y MAX funcionan con fechas y textos:** `MIN(fecha)` devuelve el primer pedido.
- **SUM sobre cero filas devuelve NULL, no 0** (se resuelve con `COALESCE` en el Tema 9).

### GROUP BY: una fila por grupo
Imagina **cajas**: una por cada valor de la columna de agrupación; después se calcula sobre cada caja.
```sql
SELECT cliente_id, COUNT(*) AS pedidos, SUM(monto) AS total
FROM pedidos
GROUP BY cliente_id;
```
| cliente_id | pedidos | total |
|---|---|---|
| 1 | 3 | 34.60 |
| 2 | 2 | 38.00 |
| 3 | 2 | 23.30 |
| 4 | 1 | 4.00 |

> 📦 **Regla de oro: "Lo que no está agregado, va agrupado."**
> Toda columna del SELECT que no esté dentro de una agregación tiene que estar en el GROUP BY.

**Error típico:** `SELECT cliente_id, fecha, SUM(monto) ... GROUP BY cliente_id`
→ *column "pedidos.fecha" must appear in the GROUP BY clause or be used in an aggregate function*.
El cliente 1 tiene tres fechas: el motor no sabe cuál mostrar en su única fila.

- 📥 **"En GROUP BY, el NULL tiene su propia caja."** `GROUP BY ciudad` da 4 grupos: Arequipa, Lima, Trujillo y NULL (Carla). A diferencia del WHERE, aquí el NULL no desaparece.
- **Varias columnas:** `GROUP BY cliente_id, producto_id` crea una caja por cada combinación.

## 3.7 HAVING: filtrar grupos

```sql
SELECT cliente_id, SUM(monto) AS total
FROM pedidos
WHERE fecha >= '2024-03-01'      -- 1) descarta filas: quedan 104, 105, 106 y 107
GROUP BY cliente_id              -- 2) arma las cajas
HAVING SUM(monto) > 15;          -- 3) descarta cajas
```
| cliente_id | total |
|---|---|
| 1 | 20.40 |
| 2 | 18.00 |

> 🚪 **"WHERE filtra filas antes de agrupar; HAVING filtra grupos después."**

| Regla | Detalle |
|---|---|
| Condición con `SUM`, `COUNT`, etc. | Solo en HAVING |
| Condición sin agregación | En WHERE, aunque HAVING también la acepte: descartar filas temprano significa menos trabajo |
| ⚠️ Alias en HAVING | **No funciona en PostgreSQL:** `HAVING total > 15` da error → `HAVING SUM(monto) > 15` |

## 3.8 DISTINCT y LIMIT

### DISTINCT
```sql
SELECT DISTINCT ciudad FROM clientes;   -- 4 filas: el NULL aparece una sola vez
```
⚠️ **La trampa:** DISTINCT se aplica a la **combinación de todas las columnas** del SELECT.
```sql
SELECT DISTINCT cliente_id, producto_id FROM pedidos;   -- 8 filas, no 4
```
> 👯 *"DISTINCT mira la fila completa, no la primera columna."*
> 🩹 *"DISTINCT no es una curita":* si aparecen duplicados inesperados, busca la causa.

### LIMIT y OFFSET
```sql
SELECT pedido_id, monto FROM pedidos ORDER BY monto DESC LIMIT 3;   -- 104, 102, 105
```
- 🎰 **"LIMIT sin ORDER BY es una lotería."** "Los 3 mayores" siempre necesita ORDER BY.
- **`OFFSET n` salta n filas:** `LIMIT 3 OFFSET 1` devuelve los puestos 2, 3 y 4 (paginación).

### Empates en el límite (estándar SQL)
```sql
SELECT pedido_id, cantidad
FROM pedidos
ORDER BY cantidad DESC
FETCH FIRST 4 ROWS WITH TIES;   -- 5 filas: los pedidos 100 y 106 empatan en el 4.º puesto
```
`LIMIT 4` mostraría solo uno de los dos empatados, elegido al azar.

## 3.9 Orden de escritura frente a orden de ejecución ⭐

| Escritura | Ejecución |
|---|---|
| 1. SELECT | 1. **FROM** |
| 2. FROM | 2. **WHERE** |
| 3. WHERE | 3. **GROUP BY** |
| 4. GROUP BY | 4. **HAVING** |
| 5. HAVING | 5. **SELECT** |
| 6. ORDER BY | 6. **ORDER BY** |
| 7. LIMIT | 7. **LIMIT** |

> 🦘 **"El SELECT salta al quinto lugar."**
> La ejecución sigue el mismo orden que la escritura, con una sola diferencia: el SELECT pasa detrás del HAVING.

### La analogía de la cocina 👨‍🍳
| Paso | Cláusula | En la cocina |
|---|---|---|
| 1 | FROM | Sacar los ingredientes de la despensa |
| 2 | WHERE | Descartar los ingredientes malos |
| 3 | GROUP BY | Separar en bandejas |
| 4 | HAVING | Descartar las bandejas que no sirven |
| 5 | SELECT | **Emplatar:** elegir qué se ve y ponerle nombre (alias) |
| 6 | ORDER BY | Ordenar los platos en la mesa |
| 7 | LIMIT | Servir solo algunos |

### Consecuencias
| ¿Se puede…? | Respuesta | Por qué |
|---|---|---|
| Usar un alias en WHERE | ❌ | Todavía no se emplató: el nombre no existe |
| Usar un alias en HAVING | ❌ (PostgreSQL) | Igual: HAVING ocurre antes del SELECT |
| Usar un alias en ORDER BY | ✅ | Se ordena después de emplatar |
| Poner una agregación en WHERE | ❌ | Las bandejas todavía no existen |
